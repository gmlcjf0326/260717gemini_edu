# 교육과정 개요 — 「20분 만에 이해하는 AI」 중1 제미나이 수업 패키지

> **기준일**: 2026년 7월. AI 서비스의 정책·기능은 수시로 바뀌므로, 수업 전 반드시 실제 접속 화면과 공식 문서로 재확인하십시오. 근거 자료는 `appendix/제미나이-조사-정리.md`에 정리되어 있습니다.
>
> **이 문서의 용도**: 패키지 전체의 설계 의도와 구조를 한눈에 파악하는 관제탑 문서입니다. 개별 차시의 진행 방법은 각 지도안(`curriculum/1~4차시-*.md`)이, 수업 전 점검은 `teacher-kit/사전준비-체크리스트.md`가 담당합니다.

## 1. 설계 철학 — 왜 이렇게 만들었나

### 1-1. 왜 게스트 모드인가

이 패키지의 본편 4개 차시는 전부 **제미나이(Gemini) 웹의 게스트 모드(로그인 없이 사용)** 를 전제로 설계했습니다. 이유는 세 가지입니다.

첫째, **법적·행정적 부담의 원천 회피**입니다. 한국에서 개인 구글 계정을 스스로 관리할 수 있는 연령은 만 14세 이상인데, 중1 학생 상당수는 만 14세 미만입니다. 또한 개인정보 보호법 제22조의2는 만 14세 미만 아동의 개인정보 처리에 동의가 필요한 경우 법정대리인의 동의를 받고 이를 확인할 의무를 규정합니다. 수업 중 개인 계정 로그인을 지시하면 이 동의·확인 절차 문제가 곧바로 발생합니다. 게스트 모드는 로그인 자체가 없으므로 계정·연령 확인 이슈를 처음부터 만들지 않습니다.

둘째, **접속 장벽 최소화**입니다. 25~30명이 20분 안에 실습까지 마쳐야 하는 수업에서, 계정 배부·비밀번호 분실·로그인 오류는 수업을 통째로 삼키는 변수입니다. 게스트 모드는 "주소 입력 → 로그인 없이 사용 선택 → 입력창 확인" 3단계면 끝납니다.

셋째, **본편 학습 목표에 텍스트 대화면 충분**하기 때문입니다. 게스트 모드에서는 텍스트 대화·창작·요약·번역이 가능하고, 이미지 생성·파일 업로드·대화 기록 저장은 불가능합니다. 본편 4개 차시는 이 제약 안에서 완결되도록 설계했으며, 이미지 생성은 학교 Workspace for Education 계정이 확보된 경우에만 `extensions/확장팩-이미지-생성-차시.md`로 분리해 두었습니다.

게스트 모드 전제에서 파생되는 운영 수칙 두 가지는 모든 문서에 반복해서 심어 두었습니다.

- **대화 기록은 창을 닫으면 사라진다** → 마음에 드는 결과는 그 자리에서 학습지에 옮겨 적거나 복사하는 습관을 1차시부터 지도합니다.
- **지역·시점·네트워크에 따라 게스트 접속이 막힐 수 있다** → 수업 전 학교 네트워크에서 시크릿 창으로 3회 접속 테스트를 필수로 하고, 실패 시 플랜 B(학교 계정 또는 교사 시연)로 전환합니다.

### 1-2. 왜 20분 × 4회인가

45분 정규 수업이 아니라 **20분 단위 4회**로 쪼갠 것은 의도적입니다.

- **끼워 넣기 쉬운 규격**: 아침활동, 창의적 체험활동, 교과 수업의 도입·마무리 연계 등 학교의 자투리 시간 구조에 그대로 들어갑니다. "AI 수업을 하고 싶지만 한 차시를 통째로 빼기 어렵다"는 현실적 제약에 맞춘 규격입니다.
- **집중 시간과의 궁합**: 중1에게 20분은 "하나의 개념 + 하나의 실습"을 소화하기에 적절한 길이입니다. 각 차시는 도입(3분) → 개념(3~4분) → 실습(9~10분) → 정리(3~4분)의 공통 골격을 따르고, 타임라인 합은 정확히 20분입니다.
- **간격 반복 효과**: 4회에 걸쳐 "확률 생성 → 프롬프트(AI에게 건네는 질문·부탁의 말) → 환각(할루시네이션)·검증 → 윤리"를 쌓아 올리면서, 매 차시 앞 차시의 핵심(특히 1차시의 '확률로 말을 만든다')을 다시 소환합니다. 한 번에 몰아치는 특강보다 태도 형성에 유리한 구조입니다.

### 1-3. 설계 원칙 4가지

1. **체험 먼저, 개념 나중**: 모든 차시가 언플러그드 게임·비유·실험으로 시작해 학생이 현상을 먼저 겪고, 개념어는 그 뒤에 붙입니다.
2. **어떤 결과가 나와도 수업이 성립**: 생성형 AI는 결과를 통제할 수 없습니다. 특히 3차시의 환각 실습은 환각이 재현되는 경우와 AI가 "그런 사건 없다"고 부인하는 경우 **두 갈래 모두를 수사 성공으로 처리**하도록 설계했습니다. 문서에 실은 AI 답변은 전부 "예시 답변(실제 결과는 매번 다름)"입니다.
3. **실패 대비가 본편의 일부**: 접속 실패·기기 부족은 예외 상황이 아니라 상수입니다. 모든 지도안에 플랜 B(교사 시연 전환 + 언플러그드 대체 활동)가 포함되어 있고, 운영 시나리오 3종(아래 5절)으로 어떤 기기 환경에서도 진행 가능합니다.
4. **안전이 기능보다 앞**: 개인정보 입력 금지 수칙은 1차시 첫 실습 전에 도입하고, 4개 차시 전체와 학습지·포스터·가정통신문에 반복 배치했습니다.

## 2. 4차시 아크 한눈에 보기

| 차시 | 제목 | 핵심 질문 | 핵심 개념 | 산출물 |
|---|---|---|---|---|
| 1 | AI와 첫 만남 — 인공지능은 어떻게 말할까? | AI는 어떻게 말을 만들까? | 확률 기반 생성, 개인정보 금지 수칙 | 첫 대화 기록(학습지) |
| 2 | 프롬프트의 기술 — AI에게 잘 부탁하는 법 | 어떻게 부탁해야 잘 나올까? | 프롬프트 레시피 4요소(역할–상황–요청–형식), 멀티턴 대화 | 나만의 레시피 카드 |
| 3 | AI 거짓말 탐정 — 환각 수사대 | AI의 말은 다 사실일까? | 환각, 검증 3단계(의심하기·비교하기·물어보기) | 수사 보고서 |
| 4 | AI와 함께 살아가기 — 정직한 사용 선언 | AI를 어디까지 써도 될까? | 도구 vs 대필, 정직한 표시 | 나만의 AI 사용 선언문 |

아크의 논리는 한 문장으로 요약됩니다. **"AI는 확률로 말을 만든다(1차시) → 그러니 잘 부탁하면 잘 나오고(2차시) → 그럴듯한 거짓도 만들 수 있으며(3차시) → 결국 어떻게 쓸지는 내가 정한다(4차시)."** 1차시의 확률 원리가 3차시 환각의 원인 설명으로 재등장하고, 2차시의 프롬프트 기술이 4차시의 메타 활동(AI에게 규칙 초안을 받아 내 문장으로 고쳐 쓰기)에서 다시 쓰이는 식으로, 차시 간 연결 고리를 명시적으로 걸어 두었습니다.

## 3. 역량·교육과정 연계 총괄

성취기준 코드가 아닌 영역 서술로 연계를 밝힙니다. 학교 상황에 맞게 창의적 체험활동(자율·동아리), 아침활동, 교과 수업 연계 중 어느 틀에 넣어도 무방합니다.

- **정보 교과 — 인공지능·디지털 문화 영역**: 인공지능의 기본 동작 원리(데이터 기반 확률 예측)를 체험으로 이해하고(1차시), 디지털 도구를 목적에 맞게 조작·활용하는 능력(2차시)과 연계됩니다.
- **도덕 교과 — 정보통신 윤리**: 개인정보 보호 태도(1차시), 정보의 진위를 따지는 비판적 태도(3차시), 표절·저작권·타인 초상 존중 등 디지털 시민성(4차시)과 연계됩니다.
- **국어 교과 — 쓰기·매체 영역**: 매체가 생성한 글을 비판적으로 읽고 비교하는 활동(1·3차시), 목적에 맞게 요청문을 쓰고 고쳐 쓰는 활동(2차시), 초안을 자기 문장으로 재구성하는 쓰기 윤리(4차시)와 연계됩니다.

핵심 역량 면에서는 **지식정보처리 역량**(정보의 생성 원리 이해와 검증), **의사소통 역량**(프롬프트 작성, 결과 비교 토의), **공동체 역량과 자기관리 역량**(안전 수칙 실천, 사용 규칙 자기 결정)을 기릅니다.

**교사**

- 시연용 기기 1대 + 대형 화면(TV/프로젝터) 미러링
- **게스트 접속 사전 테스트**: 학교 네트워크에서 시크릿 창으로 gemini.google.com 3회 접속 (3회 성공 시 게스트 확정, 실패 시 플랜 B)
- 실습 프롬프트 사전 실행: `teacher-kit/프롬프트-스니펫-모음.md`의 해당 차시 프롬프트를 학생과 동일한 환경에서 직접 돌려 결과 적절성 확인
- 인쇄물: 해당 차시 학습지(학급 인원수 + 여유분), `teacher-kit/안전수칙-포스터.md`(인쇄는 1차시 전 1회, 게시는 각 수칙이 도입되는 차시에 한 장씩 추가하는 방식 권장 — 게시 요령은 포스터 문서 참고)
- 타이머(20분 수업은 시간 관리가 생명입니다)

**학생**

- 1인 1기기(크롬북/태블릿/PC) — 충전 상태 확인
- 필기구 (기록 저장이 안 되므로 옮겨 적기가 필수입니다)

**학교·환경**

- 네트워크에서 gemini.google.com 접속 허용 여부(필터링 정책) 확인
- 학부모 대상 사전 안내: `teacher-kit/학부모-안내문.md` 발송 권장 (게스트 모드는 로그인·계정 수집이 없어 별도 동의서가 필요한 형식은 아니며, 안내 목적입니다)
- (학교 계정 경로 선택 시에만) 관리자 활성화 여부 + 보호자 동의 이력 확인

## 5. 운영 시나리오 3종

기기 환경에 따라 세 가지 시나리오 중 하나를 고릅니다. 모든 지도안은 시나리오 A를 기본으로 쓰되, B·C로의 전환 절차를 각 지도안 플랜 B 절에 담고 있습니다. 수업 중에도 접속 상황이 나빠지면 A → B → C 순으로 즉시 내려앉을 수 있습니다.

### 시나리오 A — 1인 1기기 (기본)

- **조건**: 학급 전원 기기 확보 + 게스트 접속 3회 테스트 성공.
- **진행**: 지도안 그대로. 전원이 동시에 같은 프롬프트를 입력하고 옆 친구와 결과를 비교하는 활동(1차시 미션1 등)이 가장 큰 효과를 냅니다.
- **유의점**: 실습 시작 전 "입력창이 보이는 사람 손!"으로 전원 접속을 확인하고 출발합니다. 접속 못 한 학생은 옆 친구와 짝을 지어 진행시키고 수업 후 개별 지원합니다.

### 시나리오 B — 모둠 1기기

- **조건**: 기기가 모둠당 1대(학급당 5~8대) 수준일 때.
- **진행**: 모둠 내 역할을 나눕니다 — **입력 담당**(프롬프트 타이핑), **기록 담당**(결과를 학습지에 옮겨 적기), **검증/발표 담당**(결과 읽고 이상한 점 찾기, 전체 공유). 미션마다 역할을 한 칸씩 돌려 전원이 입력을 경험하게 합니다.
- **유의점**: 실습 시간을 지도안보다 1~2분 길게 잡고, 그만큼 개념 설명을 압축합니다. "결과 비교" 활동은 짝 비교 대신 모둠 간 비교로 바꿉니다.

### 시나리오 C — 교사 시연 (기기 0대 또는 접속 전면 실패)

- **조건**: 학생 기기가 없거나, 수업 당일 게스트 접속이 막혔을 때.
- **진행**: 교사 기기 1대를 대형 화면에 미러링하고, **프롬프트는 학생이 만들고 입력만 교사가 대행**합니다. "다음에 뭐라고 부탁할까?"를 계속 학생에게 넘겨 참여를 유지합니다. 각 지도안의 플랜 B 절에 차시별 언플러그드 대체 활동(예: 1차시 '다음 단어 맞히기' 확장판)이 준비되어 있습니다.
- **유의점**: 시연 결과도 학생이 각자 학습지에 기록하게 하여 산출물은 동일하게 남깁니다. 시연 중 부적절한 답변이 나올 가능성에 대비해 교사가 화면을 먼저 훑고 읽어 줍니다.

## 6. 안전·법적 고려 요약

상세 근거와 출처는 `appendix/제미나이-조사-정리.md` 2·3절을 보십시오. 본 패키지와 해당 문서는 수업 설계 참고 자료이며 **법률 자문이 아닙니다**. 최종 판단은 공식 문서·학교 규정·담당 부서 협의를 따릅니다.

### 6-1. 연령·계정 정책 (2026년 7월 조사 시점 기준)

- 한국에서 개인 구글 계정 자체 관리 연령은 **만 14세 이상** → 중1 대부분 미달. 개인 계정 로그인 지시는 하지 않습니다.
- **Google AI Studio는 만 18세 이상 전용** → 수업 사용 불가.
- **게스트 모드는 계정·연령 확인이 없음** → 본 수업의 1순위.

### 6-2. 국내 법령

## 7. 패키지 사용법 — 어떤 문서를 언제 읽나

**처음 잡았을 때 (수업 1~2주 전)**

1. 이 문서(00-교육과정-개요)로 전체 구조 파악
2. `appendix/제미나이-조사-정리.md`로 정책 근거 확인 → 우리 학교 조건(네트워크, 기기, 학교 계정 유무)에 대입해 운영 시나리오(A/B/C) 잠정 결정
3. `teacher-kit/학부모-안내문.md` 발송 준비

**수업 준비 (D-7 ~ 당일 아침)**

4. `teacher-kit/사전준비-체크리스트.md`를 단계별로 실행 (게스트 접속 3회 테스트 포함)

6. `teacher-kit/프롬프트-스니펫-모음.md`에서 해당 차시 프롬프트를 직접 실행해 보기
7. `worksheets/`에서 해당 차시 학습지 인쇄

**수업 중**

8. 지도안의 분 단위 흐름표 + 스니펫 모음을 옆에 두고 진행

10. `teacher-kit/평가-루브릭.md`로 관찰 체크·산출물 평가·(4차시 후) 자기평가·기록
