# 사전 준비 체크리스트 — 「20분 만에 이해하는 AI」 (교사용)

> **적용 범위**: 본편 4개 차시(게스트 모드 전제) 공통. 확장 차시(이미지 생성)는 별도 조건이 있으므로 `extensions/확장팩-이미지-생성-차시.md`의 사전 조건 절을 함께 확인하십시오.

- 단계는 **D-7(일주일 전) → D-1(전날) → 당일 아침 → 쉬는 시간(수업 직전) → 수업 직후** 5단계입니다. 위에서 아래로 체크하면 됩니다.

## 경로 결정 트리 (가장 먼저 이해할 것)

리서치 결론(`appendix/제미나이-조사-정리.md` 1·6절)에 따라 수업 경로는 세 가지이며, 우선순위가 정해져 있습니다.

| 우선순위 | 경로 | 확정 조건 |
|---|---|---|
| ① | 게스트 모드 (로그인 없이 사용) | 학교 네트워크 + 시크릿 창에서 접속 테스트 **3회 연속 성공** |
| ② | 학교 Workspace for Education 계정 | 게스트 실패 + 관리자 활성화 확인 + 보호자 동의 이력 확인 완료 |
| ③ | 교사 시연 + 언플러그드 | ①·② 모두 불가할 때. 각 차시 지도안의 "플랜 B" 절 사용 |

**주의**: 어떤 경우에도 학생 개인 구글 계정 로그인은 지시하지 않습니다. 한국의 구글 계정 자체 관리 연령은 만 14세 이상이며, 만 14세 미만 아동의 개인정보 처리에는 법정대리인 동의·확인 의무(개인정보 보호법 제22조의2)가 따르기 때문입니다. 게스트 모드는 로그인 자체가 없어 이 문제를 원천 회피합니다.

## D-7 (수업 일주일 전)

행정 협의와 예약이 필요한 항목입니다. 하루 만에 안 되는 것들이므로 일주일 여유를 두십시오.

### 네트워크·기기

- [ ] 정보부장(또는 네트워크 담당자)에게 **gemini.google.com이 학교 유해차단 필터링에서 열리는지** 확인 요청했다. 차단되어 있다면 수업용 예외(화이트리스트) 처리를 요청했다.
- [ ] 학생용 기기(크롬북/태블릿/PC)를 수업 날짜·교시에 맞춰 **예약**했다(1인 1기기 목표, 최소 모둠당 1기기 확보).
- [ ] 기기 대수를 세어 **부족분 대비 운영 방식**을 정했다(1인 1기기 / 모둠 1기기 / 교사 시연 중 무엇으로 할지 — `curriculum/00-교육과정-개요.md`의 운영 시나리오 3종 참고).
- [ ] 교실의 교사용 화면(TV/프로젝터/전자칠판)이 교사 기기와 정상 연결되는지 확인했다.

### 경로 확정을 위한 1차 테스트

- [ ] **학교 네트워크**에서, **시크릿 창(로그인 정보가 남지 않는 창)**으로 gemini.google.com에 접속해 "로그인 없이 사용"이 가능한지 1차 확인했다. (본 테스트 3회는 D-1에 실시 — 여기서는 가능 여부만 미리 확인)
- [ ] 1차 확인에서 게스트 접속이 안 되는 경우: **학교 계정 경로**를 검토하기 시작했다. 즉,
  - [ ] 관리자(정보부장)에게 학교 Workspace for Education에서 **Gemini 앱이 활성화되어 있는지** 확인 요청했다. (2025년 8월 13일부터 교육용 핵심 서비스로 적용된 것으로 안내되었으나, 개별 학교가 비활성화했을 수 있음 — 리서치 5절)
  - [ ] 학교 계정 발급 시점의 **보호자 동의 이력**을 개인정보 담당자에게 확인 요청했다. (리서치 3·9절)
  - [ ] 학교 계정 경로를 실제로 쓰기로 했다면, `teacher-kit/학부모-안내문.md`의 "학교 계정 사용 시 별도 안내" 예비 문구 포함 여부를 결정했다.

### 문서·안내

- [ ] `teacher-kit/학부모-안내문.md`를 학교 양식에 맞게 옮겨 **가정통신문 발송(또는 알림장 게시)** 절차를 시작했다. (게스트 모드는 로그인·계정 수집이 없어 회신 동의서가 필요한 형식은 아니며 '안내' 목적임)
- [ ] 4개 차시 지도안(`curriculum/1차시~4차시`)을 한 번 통독하고, 우리 학급 상황에 맞게 손볼 부분(학급 인원, 모둠 수, 시간대)을 메모했다.
- [ ] 관리자(교감/부장)에게 수업 취지와 게스트 모드 전제(로그인 없음)를 구두 또는 메모로 공유했다.

## D-1 (수업 전날)

기술 검증과 인쇄물 준비의 날입니다. 리서치 9절의 "수업 직전 확인 체크 3가지"가 모두 이 단계에 들어 있습니다.

### 접속 테스트 (가장 중요)

- [ ] **학교 네트워크 + 시크릿 창에서 게스트 접속을 3회 테스트**했다. 매회 새 시크릿 창을 열어 "주소 입력 → 로그인 없이 사용 선택 → 대화 입력창 확인 → 짧은 질문 1개 전송 → 답 수신"까지 확인했다.
  - [ ] **3회 모두 성공** → 게스트 모드 확정. 아래로 진행.
  - [ ] **1회라도 실패** → 경로 결정 트리에 따라 학교 계정(활성화·동의 확인 완료 시) 또는 교사 시연으로 전환을 확정하고, 해당 차시 지도안의 "플랜 B" 절을 다시 읽었다.
- [ ] 가능하면 **학생용 기기 1대를 빌려 같은 테스트를 1회** 반복했다. (교사 PC와 학생 기기의 필터링 정책이 다른 학교가 있음)

### 스니펫 사전 실행

- [ ] `teacher-kit/프롬프트-스니펫-모음.md`에서 **내일 차시의 실습 프롬프트(AI에게 건네는 질문·부탁의 말) 전부**를, 학생과 동일한 환경(게스트 모드)에서 **직접 실행**해 보았다.
- [ ] 결과가 수업에 적절한지(부적절 표현·과도한 길이·엉뚱한 방향 없음) 확인했고, 필요하면 스니펫의 "변형 버전"으로 교체를 결정했다.
- [ ] (3차시 전날에 해당) 세종대왕 맥북프로 프롬프트를 실행해 **환각이 나오는지, 부인하는지** 오늘 시점의 경향을 확인했다. 어느 쪽이 나와도 수업이 성립하도록 지도안(`curriculum/3차시-지도안-AI-거짓말-탐정.md`)의 두 갈래 시나리오를 복습했다.

### 기기·물품

- [ ] 학생용 기기 **전원·충전 상태**를 확인했다(충전함 통전, 충전 케이블 꽂힘 여부까지 눈으로 확인).
- [ ] 학생용 기기 2~3대를 표본으로 켜서 브라우저가 정상 실행되고 한글 입력이 되는지 확인했다.
- [ ] 예비 기기(고장·방전 대비) 2~3대를 별도로 표시해 두었다.

### 인쇄물

- [ ] 내일 차시의 학습지(`worksheets/` 해당 파일)를 학급 인원수 + 여유분 3장 **인쇄**했다.
- [ ] (1차시 전날) `teacher-kit/안전수칙-포스터.md`를 인쇄해 교실 게시 위치를 정했다.
- [ ] 판서 계획(지도안의 판서/화면 계획 절)에 필요한 자료(주소 크게 쓴 카드, 미션 문구 등)를 준비했다.

### 마지막 점검

- [ ] `teacher-kit/트러블슈팅-가이드.md`의 맨 앞 "공통 전환 사다리"를 다시 읽고, 인쇄해서 교탁에 둘 준비를 했다.
- [ ] `teacher-kit/학생-돌발질문-FAQ.md`를 훑어보며 예상 질문 답변을 머리에 넣었다.

## 쉬는 시간 (수업 직전)

리서치 7절: "쉬는 시간에 미리 접속시키면 실습 시간이 절약된다." 20분 수업에서는 이 3~5분이 실습 시간을 좌우합니다.

- [ ] 기기를 미리 배부했다(또는 모둠별 수령 담당자를 지정해 가져가게 했다).
- [ ] 학생들에게 **접속 3단계**를 안내했다: "① 주소 입력(gemini.google.com) ② '로그인 없이 사용' 선택 ③ 대화 입력창이 보이면 손 들기". **아직 아무것도 입력하지 말 것**을 함께 안내했다.
- [ ] 접속이 안 되는 학생 자리(있다면)를 파악해 두었다 — 수업 시작 후 해당 학생은 옆 친구와 짝 활동으로 즉시 전환(트러블슈팅 가이드 상황 9 참조).
- [ ] 로그인 화면에 이메일을 입력하려는 학생이 없는지 한 바퀴 돌며 확인했다("로그인은 하지 않습니다. 오늘은 로그인 없이 쓰는 날이에요").
- [ ] 학습지를 배부했다(또는 분단별 배부 준비).
- [ ] 칠판/화면에 오늘의 미션 문구를 띄웠다.

## 수업 직후

다음 차시의 품질은 직후 5분 기록에서 나옵니다.

- [ ] 학생들이 **브라우저 창(탭)을 모두 닫았는지** 확인했다. 게스트 모드 대화는 창을 닫으면 사라지므로, 닫는 것 자체가 뒷정리이자 개인정보 보호 조치입니다. (마음에 드는 결과는 수업 중에 학습지에 옮겨 적었어야 함 — 다음 차시에 이 습관을 다시 강조)
- [ ] 기기를 회수해 **충전함에 꽂고 통전**을 확인했다(다음 반·다음 차시 대비).
- [ ] 학습지 처리 원칙을 지켰다: **1~3차시 학습지는 걷지 않고** 학생이 보관하도록 안내했다(1차시 학습지는 2차시에, 2차시 레시피 카드는 3차시 함정 질문 만들기에, 3차시 수사 보고서는 4차시 '탐정 경력'으로 재사용 — 각 지도안의 다음 차시 예고 멘트 참고). **4차시 종료 후** 학습지 4종을 일괄 수합해 평가 자료로 보관한다(4차시 선언문은 게시가 우선이므로, 게시 기간이 끝난 뒤 수합 — `teacher-kit/평가-루브릭.md` 3절).
- [ ] (1차시 직후 작성, 이후 차시 갱신) 학습지·산출물에는 실명 대신 **별명만** 적히므로, 순회 관찰용 **학급 명렬표에 학생별 별명을 병기**해 두었다. 학생에게는 4차시까지 같은 별명을 쓰도록 안내한다. 이 별명-실명 대응표가 있어야 수합한 산출물을 개인별로 식별해 `teacher-kit/평가-루브릭.md`의 산출물 루브릭(3절) 평가를 할 수 있습니다.
- [ ] 지도안의 평가 포인트(관찰 체크 항목)에 따라 **관찰 기록**을 그 자리에서 3줄 이상 메모했다(누가·무엇을·어떻게 — `teacher-kit/평가-루브릭.md` 참고).
- [ ] 오늘 발생한 **기술 문제·돌발 상황**을 메모했다(증상, 조치, 소요 시간). 반복되는 문제는 트러블슈팅 가이드 여백에 우리 학교용 메모로 추가.
- [ ] 학생이 개인정보를 입력했거나 부적절한 답변을 접한 사례가 있었다면, 트러블슈팅 가이드 상황 10·5의 후속 조치(지도·기록·필요시 보호자 공유)를 이행했다.
- [ ] 다음 차시 학습지 인쇄 여부와 스니펫 사전 실행(위 D-1 축약판)을 캘린더에 등록했다.

## 부록: 2~4차시용 D-1 축약판

- [ ] 시크릿 창 게스트 접속 1~3회 테스트 (직전 차시에 문제가 있었다면 반드시 3회)
- [ ] 해당 차시 스니펫 전부 사전 실행 (특히 3차시: 환각/부인 경향 확인)
- [ ] 해당 차시 학습지 인쇄 (인원 + 3장)
- [ ] 기기 충전 상태 확인
- [ ] 지도안 타임라인 1회 리허설
